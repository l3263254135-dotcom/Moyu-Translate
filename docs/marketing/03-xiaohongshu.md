# 小红书图文内容制作

## 1. 账号定位

名称保持与软件一致，简介使用“场景 + 核心动作 + 平台”：`Mac/Windows 屏幕悬浮翻译｜长按 Option/Alt 原地读懂｜本地优先`。

内容不要包装成泛英语学习账号。主定位是“效率工具实测”，英语知识是辅助栏目。

## 2. 适合的内容类型

- 15 秒功能演示：一张图说明触发前后。
- 场景笔记：看英文游戏、读论文、追字幕。
- 对比笔记：复制粘贴与悬停翻译的操作步数，不贬低或攻击其他软件。
- 安装避坑：权限、SmartScreen、语言包。
- 更新前后：旧问题、修改内容、用户能感受到的变化。

首月每周 2-3 篇。一个素材可改写为“功能演示”“安装教程”“开发记录”三种角度，但不要连续发布近似内容。

## 3. 图片制作

建议使用 3:4 竖图。封面只保留：一个场景截图、一句 8-14 字标题、Moyu 猫咪图标。不要把完整操作教程塞进封面。

基础工具：

- 截图：macOS 截图、Windows 截图工具、Snipaste。
- 排版：Canva、Figma、稿定设计。
- 简单修图：醒图、Photoshop Express。
- 敏感信息处理：截图工具马赛克或不透明色块；不要只用轻度模糊。

推荐 6 页结构：

1. 封面：`英文游戏看不懂，不用切窗口了`。
2. 痛点：过去需要截图、切换、粘贴。
3. 操作：光标停住，长按 Option/Alt。
4. 结果：主释义、音标和例句。
5. 隐私：本地词典、OCR 和语言包。
6. 下载与系统要求。

## 4. 文案结构

第一句写场景，不写“今天给大家推荐一款软件”。示例：

`玩英文独立游戏时，最打断节奏的不是生词，而是必须切出去查。`

正文按“问题 - 动作 - 结果 - 限制 - 下载”展开。明确说明 Beta 未签名和独占全屏限制，可信度比夸张承诺重要。

## 5. 标签

每篇选择 4-8 个相关标签，组合品牌、工具和场景：

- `#MoyuTranslate`
- `#翻译软件`
- `#效率工具`
- `#Mac软件` 或 `#Windows软件`
- `#论文阅读`、`#英语学习`、`#独立游戏`

不要复制热门笔记中不相关的标签。

## 6. 发布时间与互动

首月用两个稳定时间测试：工作日 12:00-13:30，或 19:30-22:00。连续四周记录曝光、收藏、主页访问和下载点击，再决定最适合自己的时间。

评论回复原则：

- 问功能：直接回答，并附对应教程。
- 报问题：感谢信息，询问系统版本和复现步骤，引导至 GitHub Issue。
- 质疑隐私：解释本地数据流，不用“绝对安全”之类无法证明的表达。
- 提竞品：说明 Moyu 的设计取舍，不攻击其他产品。

## 7. 发布检查表

- [ ] 封面标题在手机缩略图中可读。
- [ ] 图片为同一颜色和字体系统。
- [ ] 没有暴露通知、用户名和文件路径。
- [ ] 文案包含真实限制和系统要求。
- [ ] 下载入口指向官方页面或 GitHub。
- [ ] 发布后 24 小时内集中回复有效评论。
