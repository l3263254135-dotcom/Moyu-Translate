# 30 天启动计划

## 第 1 周：建立可信入口

### 第 1-2 天

- 检查 GitHub README、License、Release 和 Issue 模板。
- 部署中英文官网，验证两个下载按钮。
- 创建用于演示的无隐私测试环境。

### 第 3-4 天

- 完成公众号、小红书和 B 站账号资料。
- 制作统一头像、横版头图和 3:4 封面模板。
- 准备“产品一句话”“三个卖点”“已知限制”固定文案。

### 第 5-7 天

- 邀请 10 位种子用户完成安装测试。
- 记录每个人卡住的步骤，不远程替他完成。
- 根据真实问题补充官网 FAQ 和教程。

## 第 2 周：发布入门内容

- 公众号：发布完整安装与权限教程。
- 小红书：发布功能演示、Mac 安装、Windows 安装三篇。
- B 站：发布三分钟双平台安装视频。
- GitHub：建立“安装失败”“OCR 失败”“语言包失败”Issue 标签。

本周目标不是追求曝光，而是把“看到内容 - 下载 - 安装 - 第一次触发”的路径跑通。

## 第 3 周：证明场景价值

- 公众号：发布论文/PDF 场景深度教程。
- 小红书：发布游戏、视频字幕、论文三种场景。
- B 站：发布图片、视频和游戏的完整演示。
- 征集 5 个用户真实场景并完成兼容性复测。

每篇内容使用不同示例，不反复展示同一个 `ability` 查询。

## 第 4 周：复盘与迭代

- 发布一次更新公告，说明修复来源和实际变化。
- 统计下载点击、安装问题、收藏/评论和有效反馈。
- 选出表现最好的两个场景，作为下月重点。
- 删除无效选题，不为保持频率发布重复内容。
- 更新 30 天后的路线图，列出已完成、正在做和暂不做。

## 数据记录表

每篇内容记录：平台、日期、主题、曝光、完整阅读/播放、收藏、评论、主页访问、下载点击和有效问题数。不要跨平台直接比较曝光量，重点看同一平台内的变化。

## 首月完成定义

- 两个平台至少各有 5 台真实设备完成安装与触发。
- 官网下载与教程不存在阻断问题。
- 已知限制已公开，不依靠评论区临时解释。
- 反馈能进入 GitHub 并具备复现信息。
- 已形成下月可持续的每周节奏，而不是一次性刷屏。
